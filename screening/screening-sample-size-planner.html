A random sample of the whole corpus is nearly worthless: at a 1.5% include rate, 300 random records contain about 4 included studies, and 4-for-4 proves only that recall exceeds 40%. Every included study the AI correctly advanced tells you nothing you didn't already know. The information lives entirely in the pile the AI rejected — so sample there, and count how many included studies are hiding in it.

What actually improves with screening

The model does not learn. The rubric does.

Nothing in a zero-shot screener updates from the records it has seen — run it on record 3,000 and it behaves exactly as it did on record 1. There is no learning curve to wait out.

What improves is the rubric, and only through a human noticing a systematic error and writing a rule against it. This project's own instruction — never exclude because duration is not mentioned; duration is often only in a baseline table — exists because someone saw that failure happen. That is the entire mechanism.

So the useful early question is not "when is it accurate?" but "how many included studies must I lay eyes on before a blind spot shows itself?"

Why the union rule dissolves the question

Run the AI as a second screener alongside a human, and advance a record if either advances it. Then:

recall(union) = P(human advances or AI advances) ≥ P(human advances) = recall(human alone)

This is an identity, not an estimate. It holds if the AI's recall is 100% and it holds if the AI's recall is zero, because a union can only add records, never remove them. The number of titles you must screen before it is safe to add the AI is zero.

Validation is therefore not a safety gate — it never was. It answers one narrower question: may I now stop paying a human to screen? And the tables above price that permission at a large fraction of the corpus, which is precisely the work the AI was meant to save. For a review of this size the two goals are in direct conflict, and the union rule is the resolution rather than the compromise.

What to do on a new 3,000-record review

  1. Calibrate before you count. Screen the first 150–200 records both ways and read every disagreement. You are hunting for rules to add to the rubric, not computing a recall figure — the sample is far too small for one, and treating it as evidence of accuracy is the main way this goes wrong.
  2. Freeze the rubric, then version it. Once edits stop changing decisions, fix the wording and record the model ID and date. Any later change invalidates everything measured before it.
  3. Run the union rule across the full corpus. One human, one AI, advance on either. Recall is guaranteed no worse than the human alone, so no validation is owed before you start.
  4. Audit the reject pile continuously. Sample from what both screeners dropped and bank the reads against the table above. This is the only sampling that buys statistical power.
  5. Report the bound you actually reached. Give the lower confidence limit and the number of included studies it rests on. A recall of "100%" on 28 studies is a claim of roughly 88% — state it that way and the method survives peer review.
